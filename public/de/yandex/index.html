Was ist Yandex DNS?

Yandex DNS ist ein kostenloser öffentlicher DNS-Dienst von Yandex (Russland). Die normalen DNS-Adressen sind 77.88.8.8, 77.88.8.1 (IPv6: 2a02:6b8::feed:0ff, 2a02:6b8:0:1::feed:0ff), verschlüsseltes DNS gibt es auch: DoT, DoH. Er ist vor allem für eine Region gedacht (Russland): In der Nähe kann er der schnellste sein, aus der Ferne ist er meist langsamer als die großen weltweiten Dienste.

Er prüft kein DNSSEC (Signaturen der Domains). Er filtert nichts: Alle Namen werden ganz normal aufgelöst.

Server-Adressen von Yandex DNS

Um Yandex DNS zu nutzen, trag Folgendes ein:

DNS (IPv4) 77.88.8.8, 77.88.8.1

DNS (IPv6) 2a02:6b8::feed:0ff, 2a02:6b8:0:1::feed:0ff

DoT / Privates DNS common.dot.dns.yandex.net

DoH https://common.dot.dns.yandex.net/dns-query

Yandex DNS einrichten

Windows 11

Einstellungen → Netzwerk und Internet → WLAN oder Ethernet → Hardwareeigenschaften → DNS-Serverzuweisung → Bearbeiten → Manuell. IPv4 einschalten und 77.88.8.8, 77.88.8.1 eintragen. Zum Verschlüsseln DNS über HTTPS auf Ein (manuelle Vorlage) stellen und https://common.dot.dns.yandex.net/dns-query eintragen.

macOS

Systemeinstellungen → Netzwerk → WLAN (oder Ethernet) → Details → DNS: auf + klicken und 77.88.8.8, 77.88.8.1 hinzufügen. Für verschlüsseltes DNS (https://common.dot.dns.yandex.net/dns-query) musst du ein Konfigurationsprofil installieren.

iPhone und iPad

Einstellungen → WLAN → auf ⓘ neben dem Netz tippen → DNS konfigurieren → Manuell, dann 77.88.8.8, 77.88.8.1 hinzufügen. Das gilt nur für dieses WLAN. Für verschlüsseltes DNS in jedem Netz installierst du ein DNS-Profil für https://common.dot.dns.yandex.net/dns-query.

Android

Einstellungen → Netzwerk & Internet → Privates DNS → Hostname des privaten DNS-Anbieters, dann common.dot.dns.yandex.net eintragen. Gilt in jedem Netz und ist verschlüsselt (DoT). Das Menü sieht je nach Hersteller etwas anders aus: Such in den Einstellungen nach „Privates DNS“.

Router

In der Router-Oberfläche (WAN- oder DHCP-Einstellungen) die DNS-Server auf 77.88.8.8, 77.88.8.1 setzen. Dann nutzt ihn jedes Gerät in deinem Netz.

Browser

Chrome: Einstellungen → Datenschutz und Sicherheit → Sicherheit → Sicheres DNS verwenden → Benutzerdefiniert, dann https://common.dot.dns.yandex.net/dns-query eintragen. Edge hat dieselbe Option unter Datenschutz, Suche und Dienste. Firefox: Einstellungen → Datenschutz & Sicherheit → DNS über HTTPS → Maximaler Schutz → Benutzerdefiniert, dann https://common.dot.dns.yandex.net/dns-query eintragen.

Linux

Mit systemd-resolved: DNS=77.88.8.8 77.88.8.1 in /etc/systemd/resolved.conf eintragen, dann systemctl restart systemd-resolved ausführen. Für DoT die Adresse als 77.88.8.8#common.dot.dns.yandex.net schreiben und DNSOverTLS=yes ergänzen.

Funktioniert Yandex DNS in Festlandchina?

Sein normales DNS antwortet meist, aber langsamer, weil die Server außerhalb Festlandchinas stehen, und Antworten für gesperrte Seiten können unterwegs gefälscht werden. Sein verschlüsseltes DNS (DoH, DoT) ist oft blockiert oder instabil. Am einfachsten findest du es mit dem Test auf dieser Seite heraus: Steht im Ergebnis „Aus deinem Netz nicht erreichbar“, erreicht dein Netz ihn nicht.

Yandex DNS oder Google Public DNS: Welcher ist schneller?

Keiner ist überall schneller. Es kommt darauf an, wie weit der jeweils nächste Server von dir entfernt ist und welchen Weg dein Internetanbieter dorthin nimmt. Diese Seite misst Yandex DNS in wenigen Sekunden aus deinem eigenen Netz. Um ihn mit den anderen zu vergleichen, nimm den Test auf der Startseite: Er misst alle Server der Liste und zeigt dir, welcher für dich am schnellsten ist.

Warum ist Yandex DNS bei mir langsam?

Meist liegt es an der Entfernung: Sein nächster Server ist weit weg, oder dein Anbieter nimmt einen Umweg. Mit eingeschaltetem Proxy oder VPN laufen auch die Abfragen darüber, und der Test misst die Strecke des Proxys (die Direkt-Regeln beheben das). Manche Netze bremsen oder blockieren verschlüsseltes DNS. Und ein Name, den noch niemand abgefragt hat, dauert immer länger (siehe die Erstabfrage unter dem Ergebnis). Ob ein anderer Server für dich schneller ist, zeigt dir der Test aller Server auf der Startseite.

Wie ändere ich meinen DNS?

Android 9 und neuer: Einstellungen → Netzwerk → Privates DNS, dann den DoT-Hostnamen eintragen (zum Beispiel one.one.one.one). Gilt in jedem Netz und ist verschlüsselt.

iPhone und Mac: die DNS-Server pro WLAN eintragen. Für verschlüsseltes DNS ein Konfigurationsprofil von der Website des Anbieters installieren.

Windows 11: Einstellungen → Netzwerk → deine Verbindung → DNS-Serverzuweisung → Manuell. Die Server eintragen und DNS über HTTPS einschalten.

Router: die DNS-Server in den DHCP- oder WAN-Einstellungen eintragen, dann nutzt sie jedes Gerät im Netz.

Nur im Browser: Chrome, Edge und Firefox haben eine Einstellung für sicheres DNS, in der du einen Anbieter wählst oder eine DoH-Adresse einfügst.

Jeder Server hat eine eigene Seite mit der Einrichtung Schritt für Schritt. Klick auf eine Adresse auf dieser Seite, um sie zu kopieren.

Ich nutze einen Proxy. Ist das trotzdem das Ergebnis meines Netzes?

Standardmäßig nicht. Mit eingeschaltetem Proxy oder VPN erreicht der Browser die DNS-Server über ihn: Der Test misst die Strecke des Proxys, und alle Server im Ausland wirken ungefähr so schnell wie dein Proxy-Server. Den DNS, den du auf deinem Gerät oder Router eingestellt hast, fragst du normalerweise direkt, diese Zahlen sind also nicht das, was du tatsächlich bekommst.

Um dein eigenes Netz zu testen, füg die Direkt-Regeln hinzu (der Knopf neben dem Fortschrittsbalken). Sie schicken nur die Adressen dieses Tests direkt raus, per exaktem Hostnamen und einzelner IP, und lassen den übrigen Verkehr in Ruhe. Unterstützt werden Clash/Mihomo, Surge, Shadowrocket, Quantumult X, Loon, sing-box und Xray; die meisten können die Regeln von dieser Seite laden und bleiben so aktuell.

Wie funktioniert der Test?

Dein Browser fragt jeden DNS-Server direkt; nichts läuft über diese Seite.

Zuerst verbindet er sich mit dem Server und fragt einmal drei beliebte Namen ab, damit sie in seinem Cache liegen. Das zählt nicht. Dann folgen 10 Runden mit je einer Abfrage, sodass ein kurzer Hänger deines Netzes nicht über das Ergebnis entscheidet. Jede zweite Runde fragt außerdem einen zufälligen Namen ab, den es nicht gibt.

Die Ergebnisse sind Mediane, eine einzelne langsame Abfrage zieht den Wert also nicht runter. Die Zeiten stammen aus der Netzwerk-Zeitmessung des Browsers selbst, die die Skripte der Seite nicht verzögern können. Jede Anfrage geht an eine neue URL und an allen Caches vorbei, sodass nur der DNS-Server selbst antworten kann.

Warum sind UDP und DoT geschätzt?

Weil ein Browser sie nicht messen kann. Webseiten können nur HTTPS-Anfragen stellen: Normales DNS über UDP (Port 53), verschlüsseltes DNS über TLS (DoT, Port 853) und DoQ gehen nicht. Keine Website kann das aus deinem Netz messen; wer solche Zahlen zeigt, misst von seinem eigenen Server aus oder rät.

Was diese Seite stattdessen tut: Sie schickt DoH, also verschlüsseltes DNS über HTTPS, an genau den Server, der auch UDP und DoT beantwortet (zum Beispiel https://1.1.1.1/dns-query). Steht die Verbindung, kostet eine Abfrage einen Hin- und Rückweg zu diesem Server plus seine Bearbeitungszeit. Eine UDP- oder DoT-Abfrage kostet genau das auch; HTTPS kommt mit deutlich unter einer Millisekunde dazu. Daher das ≈. Spricht der normale DNS-Server eines Anbieters kein HTTPS, siehst du ein – statt einer erfundenen Zahl.

Was eine Schätzung nicht erkennt: ein Netz, das Port 53 oder 853 sperrt, bremst oder manipuliert, HTTPS aber durchlässt.

Um UDP, DoT und DoQ echt zu messen, führ den Befehl aus dem Kommandozeilen-Kasten auf dieser Seite auf einem Server, einem Linux-Rechner oder einem Router aus. Er beherrscht alle Protokolle und testet diesen Server zusammen mit dem, mit dem er verglichen wird.

Wie verlässlich sind die Ergebnisse?

Wie gemessen wird, steht unter „Wie funktioniert der Test?“. Außerdem wird die Liste von mehreren Kontinenten aus mit scripts/verify.mjs (im Code-Repository) geprüft: Jede Adresse muss auf genau diese Art von Abfrage eine echte DNS-Antwort liefern, und DNSSEC wird getestet, nicht aus den Angaben der Anbieter übernommen.

Cloudflare, Google, Quad9, Control D, DNS.SB, DNS4EU und IIJ erlauben Webseiten, ihre Antworten zu lesen: Die Seite prüft jede einzelne und zählt nur echte. Bei den übrigen kann der Browser die Antwort zwar stoppen, aber nicht lesen.

Teste ein paarmal, am besten zu verschiedenen Uhrzeiten: Was nachts am schnellsten ist, muss es zur Stoßzeit nicht sein.

Was bedeutet Erstabfrage?

Beliebte Namen liegen schon im Cache jedes großen DNS-Servers, deshalb antworten alle schnell. Bei einem Namen, den länger niemand abgefragt hat, ist das anders: Der Server muss erst die DNS-Server der Website selbst fragen und dir dann die Antwort weitergeben. Das ist eine Erstabfrage.

Der Test nutzt zufällige Namen, die bei Cloudflare liegen; Cloudflare hat DNS-Server fast überall außer in Festlandchina. Diese Zeit hängt davon ab, wo die DNS-Server der jeweiligen Website stehen, und das ist bei jeder Website anders. Sie wird deshalb angezeigt, aber nicht gewertet. Server aus Festlandchina zeigen hier eine langsame Erstabfrage, weil die Server dieser Namen im Ausland stehen; bei chinesischen Websites sind sie schnell.

Was ist DNSSEC?

Kurz gesagt: Domains signieren ihre DNS-Einträge, damit die Antworten nicht gefälscht werden können. Ein Server, der DNSSEC prüft, kontrolliert die Signatur und lehnt Antworten ab, die nicht passen. So kann dir unterwegs niemand eine falsche Adresse unterschieben. Ein ✓ heißt, dass der Server prüft: Wir testen mit einer absichtlich kaputten Domain, dnssec-failed.org, die er ablehnen muss. Das schützt nur signierte Domains, hat aber keinen Nachteil.

Was ist ECS, und warum wird es hier nicht angezeigt?

ECS (EDNS Client Subnet) heißt: Der DNS-Server gibt einen Teil deiner IP-Adresse an die DNS-Server der Website weiter, damit ein CDN einen Server in deiner Nähe wählen kann statt in der Nähe des DNS-Servers. Downloads und Videos können dadurch schneller werden, dafür verrät es ein wenig über deinen Standort.

Es wird nicht angezeigt, weil es nicht fest ist: Bei unseren Prüfungen gab derselbe Server es von manchen Orten und über manche Protokolle weiter, von anderen nicht. Ein einfaches Ja oder Nein würde dich in die Irre führen.

Warum fehlen 114DNS und Baidu DNS?

Sie bieten nur normales DNS, und ihre Server antworten überhaupt nicht auf HTTPS: Ein Browser kann sie auf keinem Weg erreichen. Quad101 (Taiwan, China) fehlt ebenfalls: Sein DoH antwortete bei unseren Prüfungen nicht aus anderen Regionen.

Werden meine Daten gesammelt?

Nein. Die Abfragen gehen direkt von deinem Browser zu jedem DNS-Server und betreffen beliebte öffentliche Seiten und zufällige Namen; nichts davon handelt von dir. Deine Ergebnisse bleiben in deinem Browser. Nur wenn du auf Teilen klickst, werden sie in den Link zum Teilen geschrieben (die Zeiten jedes Servers, keine IP-Adresse; ob dein Land oder deine Region dabei ist, entscheidest du).

Wie bei jeder DNS-Abfrage sieht jeder Server deine IP-Adresse, und es gilt seine eigene Datenschutzerklärung. Der Code ist Open Source auf GitHub.
