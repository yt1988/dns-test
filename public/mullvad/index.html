Help

What is Mullvad DNS?

Mullvad DNS is a free public DNS service run by Mullvad VPN (Sweden). It offers encrypted DNS only (DoT, DoH); there is no public plain-DNS address. Its servers are in many places around the world, and your queries go to the nearest one.

It validates DNSSEC: answers whose signatures don't check out are refused. It doesn't filter: every name resolves as it is. Its operator states that it doesn't keep your IP address.

How to set up Mullvad DNS

Windows 11

Windows needs a plain DNS address before it can use encrypted DNS, and Mullvad DNS doesn't publish one: use it in the browser (below) or with a local DNS client such as dnscrypt-proxy.

macOS

macOS takes encrypted DNS through a configuration profile: install a DNS profile for https://dns.mullvad.net/dns-query.

iPhone and iPad

Install a DNS profile for https://dns.mullvad.net/dns-query, then turn it on in Settings → General → VPN & Device Management → DNS.

Android

Settings → Network & internet → Private DNS → Private DNS provider hostname: dns.mullvad.net. It works on every network and is encrypted (DoT). The menu differs a little by brand: search Settings for “Private DNS”.

Router

Routers take plain DNS addresses, which Mullvad DNS doesn't publish; on OpenWrt, https-dns-proxy can forward to https://dns.mullvad.net/dns-query.

Browser

Chrome: Settings → Privacy and security → Security → Use secure DNS → Custom: https://dns.mullvad.net/dns-query. Edge has the same under Privacy, search, and services. Firefox: Settings → Privacy & Security → DNS over HTTPS → Max Protection → Custom: https://dns.mullvad.net/dns-query.

Can Mullvad DNS be used in mainland China?

Its plain DNS usually answers, but more slowly, since the servers are outside mainland China, and answers for blocked sites can be forged on the way. Encrypted DNS (DoH, DoT) to it is often blocked or unstable. Run the test on this page: a row with no answer means it isn't reachable from your network.

Mullvad DNS or Quad9 DNS: which is faster?

Neither is faster everywhere: what counts is how far each one's nearest server is from you and how your provider routes there. This page times both, and every other DNS in the list, from your own network in about 20 seconds; the top of the page shows where Mullvad DNS ranks and how far it is behind the fastest.

Why is Mullvad DNS slow for me?

Usually distance: its nearest server is far away, or your provider routes there the long way. A proxy or VPN carries the queries too, and then the test measures the proxy's route (the direct rules fix that). Some networks slow down or block encrypted DNS. And a name nobody has asked it for yet always takes longer (the Uncached column). If another DNS in the list is clearly faster, switch to it.

How does the test work?

Your browser asks every resolver directly; nothing goes through this site. First it opens a connection to each and asks three popular names once, which puts them in the resolver's cache; none of that counts. Then come 10 rounds: in each, every resolver is asked once more, in a new random order, a few at a time, so a burst of trouble on your network hits all of them alike. Every other round also asks a random name that doesn't exist anywhere.

The numbers are medians, so a single slow query doesn't move them. Times come from the browser's own network timing for each request where it has it, which this page's scripts can't delay. Every URL is new and fetched past any cache, so only the resolver itself can answer.

Why are UDP and DoT estimates?

Browsers can only make HTTPS requests. They can't send a UDP query to port 53, open a TLS connection to port 853 (DoT) or speak DoQ, and no website can do that from your network. Any site that shows those numbers measures from its own server or guesses.

What the page can do: send DNS over HTTPS to the very server that answers UDP and DoT (for example https://1.1.1.1/dns-query). On an open connection, a query costs one round trip to that server plus the resolver's work, which is exactly what a UDP or DoT query costs; HTTP adds well under a millisecond. Hence ≈. Where a resolver's plain DNS server has no HTTPS, there's a – instead of a number.

What an estimate can't see: a network that blocks, slows or tampers with port 53 or 853 but leaves HTTPS alone.

To measure UDP, DoT and DoQ for real, run the command-line tool (the command under the table) on a server, a Linux box or a router: it speaks every protocol and uses the same resolver list.

How reliable are the results?

The timing method is described under the first question. On top of that, the list is checked with scripts/verify.mjs (in the repository) from more than one continent: every address must answer this exact kind of query with a real DNS answer, and DNSSEC validation is tested rather than taken from the resolvers' own claims.

Where a resolver allows it (Cloudflare, Google, Quad9, Control D, DNS.SB, DNS4EU, IIJ), the page also reads each answer and only counts real ones. For the others the browser can time the answer but not read it.

Run the test a couple of times, at different hours if you can: what is fastest at night on your network may not be at peak time.

I use a proxy. Are the results still mine?

Not by default: with a proxy or VPN on, your browser reaches the resolvers through it, and the test measures the proxy's route (all the resolvers abroad then look about as fast as your proxy server). The resolver you set on your device or router is usually asked directly, so that's not what you'd get.

To test your own network, add the direct rules (the button next to the progress): they send exactly the addresses this test asks straight out, by exact host name and single IP, and nothing else. Clash/Mihomo, Surge, Shadowrocket, Quantumult X, Loon, sing-box and Xray are covered; most can load the rules from this site so they stay current.

What does uncached mean?

Popular names are already in every busy resolver's cache, so asking for them is quick everywhere. A name nobody asked for recently makes the resolver ask that site's own DNS servers first. The test uses random names under a zone hosted on Cloudflare's DNS, which has servers almost everywhere except mainland China.

That cost depends on where each site's DNS servers are, which differs from site to site, so it's shown but not ranked. Resolvers in mainland China look slow here because the zone's servers are abroad; for Chinese sites, whose DNS servers are in China, they are fast.

Which one should I pick?

The fastest one at the top is a good default. If it's close (a few ms), prefer what else matters to you: Quad9 and OpenDNS block known malware and phishing sites; Mullvad, Quad9 and Wikimedia keep no logs of who asked what; resolvers that validate DNSSEC refuse forged answers on signed domains.

If your device only lets you enter plain DNS server addresses (most routers, older systems), look at the UDP column: the line under the winner names the fastest plain DNS when it's a different one.

For privacy from your network and ISP, use the DoT or DoH address: plain DNS travels unencrypted.

How do I change my DNS?

Android 9+: Settings → Network → Private DNS → enter the DoT host (for example one.one.one.one).

iPhone and Mac: per Wi-Fi network, enter the DNS servers; for encrypted DNS install a configuration profile from the resolver's website.

Windows 11: Settings → Network → your connection → DNS server assignment → Manual, enter the servers and set DNS over HTTPS to On.

Router: put the DNS servers in its DHCP or WAN settings and every device on the network uses them.

Browser only: Chrome, Edge and Firefox have a Secure DNS setting where you pick a provider or paste the DoH address.

What is DNSSEC?

DNSSEC lets a domain sign its DNS records. A validating resolver checks the signatures and refuses answers that don't match, so nobody on the way can hand you a forged address for a signed domain. The page shows ✓ for resolvers that do (checked with a deliberately broken domain, dnssec-failed.org, which they must refuse). It only helps for domains that are signed, but costs nothing.

Why aren't 114DNS or Baidu DNS tested?

They offer plain DNS only, and their servers don't answer HTTPS at all, so a browser can't reach them in any way. Quad101 (Taiwan) was left out because its DoH didn't answer from abroad in our checks.

What is ECS, and why isn't it shown?

EDNS Client Subnet: some resolvers tell a site's DNS servers part of your address, so a CDN can pick a server near you rather than near the resolver. It can make downloads and video faster, at a small cost in privacy.

It isn't in the table because it isn't a fixed property: in our checks the same resolver passed a subnet from some places and protocols and not from others, so any single yes or no would mislead.

Is my data collected?

No. The queries go straight from your browser to each resolver, and the names asked are popular public sites and random names; nothing about you is in them. This site receives no results. Each resolver sees your address, as with any DNS query; their own privacy policies apply. The code is open source on GitHub.
