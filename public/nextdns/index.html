Help

What is NextDNS?

NextDNS is a free public DNS service run by NextDNS, based in United States. Its plain DNS addresses are 45.90.28.0, 45.90.30.0 (IPv6: 2a07:a8c0::, 2a07:a8c1::), and it also offers encrypted DNS: DoT, DoH, DoQ. It has servers all over the world, and your queries go to the nearest one.

It checks DNSSEC (domain signatures): answers with a bad signature are refused, so they can't be forged. It doesn't filter anything: every name resolves normally. A free account lets you set your own block lists and see a query log; the public addresses work without one.

NextDNS server addresses

To use NextDNS, enter:

DNS (IPv4) 45.90.28.0, 45.90.30.0

DNS (IPv6) 2a07:a8c0::, 2a07:a8c1::

DoT / Private DNS dns.nextdns.io

DoH https://dns.nextdns.io/

DoQ quic://dns.nextdns.io

How to set up NextDNS

Windows 11

Settings → Network & internet → Wi‑Fi or Ethernet → Hardware properties → DNS server assignment → Edit → Manual. Turn on IPv4 and enter 45.90.28.0, 45.90.30.0. To encrypt it, set DNS over HTTPS to On (manual template) and enter https://dns.nextdns.io/.

macOS

System Settings → Network → Wi‑Fi (or Ethernet) → Details → DNS: click + and add 45.90.28.0, 45.90.30.0. For encrypted DNS (https://dns.nextdns.io/) you need to install a configuration profile.

iPhone and iPad

Settings → Wi‑Fi → tap ⓘ next to the network → Configure DNS → Manual, and add 45.90.28.0, 45.90.30.0. This only applies to that Wi‑Fi network. For encrypted DNS on every network, install a DNS profile for https://dns.nextdns.io/.

Android

Settings → Network & internet → Private DNS → Private DNS provider hostname, and enter dns.nextdns.io. It works on every network and is encrypted (DoT). Menus vary a little by brand: search Settings for “Private DNS”.

Router

In your router's admin page (WAN or DHCP settings), set the DNS servers to 45.90.28.0, 45.90.30.0. Every device on your network will then use it.

Browser

Chrome: Settings → Privacy and security → Security → Use secure DNS → Custom, and enter https://dns.nextdns.io/. Edge has the same option under Privacy, search, and services. Firefox: Settings → Privacy & Security → DNS over HTTPS → Max Protection → Custom, and enter https://dns.nextdns.io/.

Linux

With systemd-resolved: add DNS=45.90.28.0 45.90.30.0 to /etc/systemd/resolved.conf, then run systemctl restart systemd-resolved. For DoT, write the address as 45.90.28.0#dns.nextdns.io and add DNSOverTLS=yes.

Does NextDNS work in mainland China?

Its plain DNS usually answers, but more slowly, because the servers are outside mainland China, and answers for blocked sites can be forged on the way. Its encrypted DNS (DoH, DoT) is often blocked or unreliable. The easiest way to know is to run the test on this page: if the result says “Can't be reached from your network”, your network can't reach it.

NextDNS or AdGuard DNS: which is faster?

Neither is faster everywhere. It depends on how far each one's nearest server is from you and how your internet provider routes traffic there. This page times NextDNS from your own network in a few seconds. To compare it with the others, run the test on the home page: it times every resolver in the list and shows which is fastest for you.

Why is NextDNS slow for me?

Usually it's distance: its nearest server is far from you, or your provider takes a long route there. With a proxy or VPN on, the queries go through it too, so the test times the proxy's route (the direct rules fix that). Some networks slow down or block encrypted DNS. And a name nobody has looked up yet always takes longer (the first-lookup time under the result). To see whether another resolver is faster for you, run the test of them all on the home page.

How do I change my DNS?

Android 9 and later: Settings → Network → Private DNS, and enter the DoT hostname (for example one.one.one.one). It works on every network and is encrypted.

iPhone and Mac: enter the DNS servers for each Wi-Fi network. For encrypted DNS, install a configuration profile from the resolver's website.

Windows 11: Settings → Network → your connection → DNS server assignment → Manual. Enter the servers and turn on DNS over HTTPS.

Router: enter the DNS servers in its DHCP or WAN settings, and every device on your network uses them.

Just your browser: Chrome, Edge and Firefox have a Secure DNS setting where you pick a provider or paste a DoH address.

Each resolver's own page has step-by-step setup. Click any address on this page to copy it.

I use a proxy. Is this still my own network's result?

Not by default. With a proxy or VPN on, your browser reaches the resolvers through it, so the test times the proxy's route, and every resolver abroad looks about as fast as your proxy server. The DNS you set on your device or router is normally reached directly, so these numbers aren't what you'd actually get.

To test your own network, add the direct rules (the button next to the progress bar). They send only the addresses this test uses straight out, matched by exact hostname and single IP, and leave all other traffic alone. Clash/Mihomo, Surge, Shadowrocket, Quantumult X, Loon, sing-box and Xray are supported, and most can load the rules from this site so they stay up to date.

How does the test work?

Your browser queries each resolver directly; nothing goes through this site.

First it connects to the resolver and looks up three popular names once, so they're in its cache. That part isn't scored. Then come 10 rounds, each asking it once, so a single hiccup on your network doesn't decide the result. Every other round also looks up a random name that doesn't exist.

The results are medians, so one slow query doesn't drag a score down. Times come from the browser's own network timing, which the page's scripts can't slow down. Every request goes to a new URL and skips every cache, so only the resolver itself can answer.

Why are UDP and DoT estimated?

Because a browser can't measure them. Web pages can only make HTTPS requests: they can't send plain DNS over UDP (port 53), encrypted DNS over TLS (DoT, port 853) or DoQ. No website can measure those from your network; a site that shows such numbers measured from its own server, or guessed.

What this page does instead: it sends DoH, encrypted DNS over HTTPS, to the very server that answers UDP and DoT (for example https://1.1.1.1/dns-query). Once the connection is open, a query takes one round trip to that server plus its processing time. A UDP or DoT query costs exactly that too; HTTPS adds well under a millisecond. Hence the ≈. Where a resolver's plain DNS server doesn't speak HTTPS, you'll see a – rather than a made-up number.

What an estimate can't catch: a network that blocks, slows or tampers with ports 53 or 853 but leaves HTTPS alone.

To measure UDP, DoT and DoQ for real, run the command in the command-line box on this page on a server, a Linux machine or a router. It speaks every protocol and tests this resolver along with the one it's compared with.

How reliable are the results?

The way they're measured is under How does the test work? On top of that, the list is checked from more than one continent with scripts/verify.mjs (in the code repository): every address must answer this kind of query with a real DNS answer, and DNSSEC support is tested, not taken from the resolvers' own claims.

Cloudflare, Google, Quad9, Control D, DNS.SB, DNS4EU and IIJ let web pages read their answers, so the page checks each one and only counts real answers. For the others, the browser can time the answer but not read it.

Run the test a few times, ideally at different hours: what's fastest at night may not be at peak times.

What does First lookup mean?

Popular names are already in every big resolver's cache, so every resolver answers them quickly. A name nobody has looked up in a while is different: the resolver first has to ask that site's own DNS servers, then pass the answer on to you. That's a first lookup.

The test uses random names hosted on Cloudflare, whose DNS servers are almost everywhere except mainland China. This time depends on where each site's DNS servers are, which varies from site to site, so it's shown but not ranked. Resolvers in mainland China get a slow first lookup here because these names' servers are abroad; for Chinese sites they're fast.

What is DNSSEC?

In short: domains sign their DNS records so the answers can't be forged. A resolver that checks DNSSEC verifies the signature and refuses answers that don't match, so nobody along the way can slip you a fake address. A ✓ means the resolver checks it: we test with a deliberately broken domain, dnssec-failed.org, which it must refuse. It only protects domains that are signed, but it has no downside.

What is ECS, and why isn't it shown here?

ECS (EDNS Client Subnet) means a resolver passes part of your IP address on to a site's DNS servers, so a CDN can pick a server near you rather than near the resolver. Downloads and video can be faster, at the cost of revealing a little about where you are.

It isn't shown because it isn't fixed: in our checks, the same resolver passed it on from some places and over some protocols but not others. A single yes or no would mislead you.

Why aren't 114DNS or Baidu DNS here?

They only offer plain DNS, and their servers don't answer HTTPS at all, so a browser has no way to reach them. Quad101 (Taiwan, China) isn't included either: its DoH didn't answer from other regions when we checked.

Do you collect my data?

No results and nothing about you are kept. The test's queries go straight from your browser to each resolver, and they're for popular public sites and random names; nothing about you is in them. Your results stay in your browser. Only when you click Share are they written into the share link (each resolver's times, no IP address; including your country or region is up to you).

One thing goes to 1ms.dog's own server (in Tokyo): to show which resolver your device really uses, the page looks up a random name under l.1ms.dog, whose DNS server is ours, and after the test sends one such name through each resolver to see which of its servers answers you. That server sees the address of the resolver that asked and, if the resolver passes it on, your network (ECS: the first part of your address, such as 203.0.113.0/24). It keeps them in memory for 2 minutes for the page to fetch from api.l.1ms.dog, then forgets them; nothing is written to disk or to a log. The page shows them to you only; they are never in the share link or card.

As with any DNS query, each resolver sees your IP address, and its own privacy policy applies. The code is open source on GitHub.
