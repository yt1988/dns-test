直接接続ルール：プロキシではなく自分の回線を測る

プロキシを使っていると、ブラウザーはプロキシ経由で各 DNS に接続し、プロキシの経路を測ってしまいます。このルールはテストが使うアドレスだけを DIRECT にし、ほかの通信は変えません。

追加したらプロキシの設定を読み込み直し、もう一度テストしてください。

ヘルプ

DNS4ALL とは？

DNS4ALL は DNS4ALL が運営する無料の公開 DNS で、拠点はオランダです。通常の DNS は 194.0.5.3（IPv6：2001:678:8::3）、暗号化 DNS は DoT、DoH に対応しています。主にオランダで運営されています。近ければ最速になり得ますが、遠いと大手のグローバル網より遅いのが普通です。

DNSSEC を検証します。署名が合わない応答は拒否されます。フィルタリングはしません。すべての名前がそのまま解決されます。非営利で運営されています。

DNS4ALL の DNS サーバーアドレス

DNS4ALL を使うときに入力するもの：

DNS (IPv4) 194.0.5.3

DNS (IPv6) 2001:678:8::3

DoT / プライベート DNS dot.dns4all.eu

DoH https://doh.dns4all.eu/dns-query

DNS4ALL の設定方法

Windows 11

設定 → ネットワークとインターネット → Wi‑Fi またはイーサネット → ハードウェアのプロパティ → DNS サーバーの割り当て → 編集 → 手動。IPv4 をオンにして 194.0.5.3 を入力します。暗号化するには「DNS over HTTPS」を「オン（手動テンプレート）」にして、テンプレートに https://doh.dns4all.eu/dns-query を入力します。

macOS

システム設定 → ネットワーク → Wi‑Fi（または Ethernet）→ 詳細 → DNS で + を押し、194.0.5.3 を追加します。暗号化 DNS（https://doh.dns4all.eu/dns-query）には構成プロファイルが必要です。

iPhone と iPad

設定 → Wi‑Fi → ネットワーク横の ⓘ → DNSを構成 → 手動 で 194.0.5.3 を追加します。その Wi‑Fi だけに効きます。どのネットワークでも暗号化 DNS を使うには、https://doh.dns4all.eu/dns-query 向けの DNS プロファイルをインストールします。

Android

設定 → ネットワークとインターネット → プライベート DNS → プライベート DNS プロバイダのホスト名 に dot.dns4all.eu を入力します。どのネットワークでも有効で、暗号化されます（DoT）。メニューはメーカーによって少し違うので、設定で「プライベート DNS」を検索してください。

ルーター

ルーターの管理画面（WAN または DHCP の設定）で DNS サーバーを 194.0.5.3 にします。ネットワーク内のすべての端末がそれを使います。

ブラウザ

Chrome：設定 → プライバシーとセキュリティ → セキュリティ → セキュア DNS を使用する → カスタム に https://doh.dns4all.eu/dns-query。Edge は「プライバシー、検索、サービス」に同じ項目があります。Firefox：設定 → プライバシーとセキュリティ → DNS over HTTPS → 最大保護 → カスタム に https://doh.dns4all.eu/dns-query。

Linux

systemd-resolved の場合：/etc/systemd/resolved.conf に DNS=194.0.5.3 と書き、systemctl restart systemd-resolved を実行します。DoT を使うには、アドレスを 194.0.5.3#dot.dns4all.eu と書き、DNSOverTLS=yes を加えます。

DNS4ALL は中国本土で使えますか？

通常の DNS はたいてい応答しますが、サーバーが中国本土の外にあるため遅く、ブロックされたサイトへの応答は途中で偽造されることがあります。暗号化 DNS（DoH、DoT）はしばしば遮断されるか不安定です。このページで測ってみてください。応答のない行は、あなたのネットワークから届かないということです。

DNS4ALL と Quad9 DNS、どちらが速い？

どこでも速いほうはありません。決め手は、それぞれの最寄りのサーバーがどれだけ遠いか、プロバイダーがどんな経路でそこへ行くかです。このページは約 20 秒で、両方と一覧の他の DNS をあなたのネットワークから測ります。ページ上部に DNS4ALL の順位と最速との差が出ます。

DNS4ALL が遅いのはなぜ？

たいていは距離です。最寄りのサーバーが遠いか、プロバイダーが遠回りしています。プロキシや VPN を通すとクエリもそこを通り、測っているのはプロキシの経路になります（直接接続ルールで解決します）。暗号化 DNS を遅くしたり遮断したりするネットワークもあります。まだ誰も問い合わせていない名前は常に時間がかかります（「キャッシュなし」列）。一覧にはっきり速い DNS があれば、そちらに切り替えましょう。

テストの仕組みは？

ブラウザーが各 DNS に直接問い合わせます。このサイトは経由しません。まず各 DNS と接続を開き、人気の名前を 3 つずつ一度問い合わせてキャッシュに載せます。ここは結果に含めません。続いて 10 ラウンド：毎回すべての DNS に一度ずつ、順番を毎回シャッフルして、いくつか同時に問い合わせます。回線が一瞬詰まっても、たまたま測っていた 1 社だけでなく全社に同じように影響します。1 ラウンドおきに、どこにも存在しないランダムな名前も問い合わせます。

数値は中央値なので、1 回の遅れでは動きません。時間はブラウザー自身が記録したリクエストごとの通信時間で、ページのスクリプトに遅らされることはありません。URL は毎回新しく、キャッシュを通さないので、答えられるのはリゾルバー本人だけです。

UDP と DoT が推定なのはなぜ？

ブラウザーにできるのは HTTPS リクエストだけです。53 番ポートへの UDP 問い合わせも、853 番ポートへの TLS 接続（DoT）も、DoQ もできません。あなたの回線からこれらを測れるウェブサイトはありません。そうした数値を出すサイトは、自分のサーバーで測っているか、推測しています。

このページができるのは、UDP と DoT に答えるのと同じサーバーへ DNS over HTTPS を送ることです（例：https://1.1.1.1/dns-query）。開いた接続上では、1 回の問い合わせはそのサーバーまでの 1 往復とリゾルバーの処理で、UDP や DoT の問い合わせも同じだけかかります。HTTP の分は 1 ms にもなりません。だから ≈ です。通常 DNS サーバーが HTTPS に対応していない場合は、数字の代わりに – を表示します。

推定でわからないこと：53 番や 853 番だけをブロック・制限・改ざんし、HTTPS には手を出さない回線。

UDP・DoT・DoQ を実測するには、サーバーや Linux マシン、ルーターでコマンドラインツール（表の下のコマンド）を実行してください。すべてのプロトコルに対応し、同じ DNS リストを使います。

結果はどのくらい信頼できる？

測り方は最初の質問のとおりです。加えて、リストはリポジトリの scripts/verify.mjs で複数の大陸から確認しています。すべてのアドレスがこの形の問い合わせに本物の DNS 応答を返すこと、そして DNSSEC 検証は各社の説明ではなく実際にテストした結果です。

応答の読み取りを許可している DNS（Cloudflare、Google、Quad9、Control D、DNS.SB、DNS4EU、IIJ）では、ページが応答の中身も確認し、本物だけを数えます。それ以外は計時のみで、中身は読めません。

何度か、できれば時間帯を変えてテストしてください。夜に最速でも、混雑時間帯は違うかもしれません。

プロキシを使っています。結果は自分のもの？

そのままでは違います。プロキシや VPN がオンだと、ブラウザーはそれを経由して各 DNS に届くため、テストはプロキシの経路を測ります（海外の DNS がどれもプロキシサーバーと同じくらいの速さに見えます）。端末やルーターに設定した DNS は普段は直接問い合わせられるので、実際に得られる速さとは違います。

自分の回線を測るには、直接接続ルール（進捗の横のボタン）を追加してください。このテストが使うアドレスだけを、正確なホスト名と単一 IP で直接接続にし、ほかは変えません。Clash/Mihomo、Surge、Shadowrocket、Quantumult X、Loon、sing-box、Xray に対応し、多くはこのサイトからルールを読み込んで最新に保てます。

「キャッシュなし」とは？

人気の名前はどの大手リゾルバーにもキャッシュされているので、どこでも速く答えます。最近だれも問い合わせていない名前では、リゾルバーはまずそのサイト自身の DNS サーバーに聞きに行きます。テストでは Cloudflare の DNS でホストされたゾーンのランダムな名前を使います。Cloudflare のサーバーは中国本土以外のほぼ全世界にあります。

この時間はサイトごとの DNS サーバーの場所で変わるので、表示はしますが順位には使いません。中国本土の DNS がここで遅く見えるのはゾーンのサーバーが国外にあるためで、中国のサイト（DNS サーバーが国内）には速く答えます。

どれを選べばいい？

一番上の DNS がまず良い選択です。差が数 ms なら、ほかに大事な点で選びましょう：Quad9 と OpenDNS は既知のマルウェア・フィッシングサイトをブロックします。Mullvad、Quad9、Wikimedia はだれが何を問い合わせたかを記録しません。DNSSEC を検証する DNS は、署名されたドメインの偽の応答を拒否します。

機器に通常の DNS サーバーアドレスしか入れられない場合（多くのルーターや古いシステム）は、UDP の列を見てください。最速の通常 DNS が 1 位と違うときは、1 位の下の行に出ます。

回線やプロバイダーに問い合わせ内容を見られたくないなら、DoT か DoH のアドレスを使ってください。通常 DNS は暗号化されません。

DNS の変え方は？

Android 9 以降：設定 → ネットワーク → プライベート DNS → DoT のホスト名（例：one.one.one.one）を入力。

iPhone と Mac：Wi-Fi ネットワークごとに DNS サーバーを入力。暗号化 DNS は各社サイトの構成プロファイルをインストール。

Windows 11：設定 → ネットワーク → 接続 → DNS サーバーの割り当て → 手動で、サーバーを入力し DNS over HTTPS をオン。

ルーター：DHCP または WAN 設定に DNS サーバーを入れると、ネットワーク内のすべての機器で使われます。

ブラウザーだけ：Chrome、Edge、Firefox の「セキュア DNS」でプロバイダーを選ぶか、DoH アドレスを貼り付けます。

このページのアドレスはクリックでコピーできます。

DNSSEC とは？

DNSSEC はドメインが自分の DNS レコードに署名する仕組みです。検証する DNS は署名を確かめ、合わない応答を拒否するので、途中のだれも署名済みドメインの偽アドレスを渡せません。✓ は検証する DNS です（わざと署名を壊したドメイン dnssec-failed.org を拒否するかでテスト）。署名済みのドメインにしか効きませんが、損はありません。

114DNS や Baidu DNS がないのはなぜ？

通常 DNS しか提供しておらず、サーバーが HTTPS にまったく応答しないため、ブラウザーからは一切届きません。台湾の Quad101 も、確認時に DoH が国外から応答しなかったため外しました。

ECS とは？ なぜ表示しない？

EDNS Client Subnet：一部の DNS は、あなたのアドレスの一部をサイトの DNS サーバーに伝えます。CDN がリゾルバーではなくあなたの近くのサーバーを選べるので、ダウンロードや動画が速くなることがあり、代わりにプライバシーが少し減ります。

表にないのは固定の性質ではないからです。確認では、同じ DNS が場所やプロトコルによって伝えたり伝えなかったりしたため、はい・いいえのどちらでも誤解を招きます。

データは集められますか？

いいえ。問い合わせはブラウザーから各 DNS に直接送られ、内容は人気の公開サイトとランダムな名前だけで、あなたの情報は含まれません。このサイトは結果を受け取りません。普段の DNS 問い合わせと同じく、各 DNS にはあなたのアドレスが見え、各社のプライバシーポリシーが適用されます。コードは GitHub で公開しています。
