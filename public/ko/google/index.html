이미지와 링크는 브라우저 안에서 만들어지며 업로드되지 않습니다. 링크에는 숫자만 들어갑니다.

서버에서 UDP, DoT, DoQ 실측

브라우저는 UDP와 DoT를 추정만 할 수 있습니다. VPS나 Linux 기기, 공유기에서 이 명령을 실행하면 다섯 가지 프로토콜을 모두 실측하고 현재 DNS와도 비교합니다.

설치하고 실행 (Linux, macOS, 공유기)
curl -fsSL https://dns.1ms.dog/i | sh
dnstest를 /usr/local/bin(또는 ~/.local/bin)에 설치하고 메뉴에서 테스트할 항목을 고릅니다. 이후 언제든 dnstest로 다시 테스트하세요.
한 번만 실행, 설치 안 함
curl -fsSL https://dns.1ms.dog/i | sh -s -- run
curl이 없으면 wget으로
wget -qO- https://dns.1ms.dog/i | sh
자주 쓰는 옵션
dnstest -p udp,dot,doq
일부 프로토콜만
dnstest -r cloudflare,google,alidns
일부 DNS만 (dnstest --list로 전체 목록)
dnstest -6
IPv6로
dnstest --json > dns.json
JSON으로 출력
Windows
irm https://dns.1ms.dog/i.ps1 | iex
PowerShell에서 실행: dnstest를 설치하고 메뉴를 엽니다. 프로그램을 직접 내려받을 수도 있습니다:dnstest-windows-amd64.exe ↓

직접 연결 규칙: 프록시가 아닌 내 네트워크를 측정

프록시를 켜 두면 브라우저가 프록시를 거쳐 각 DNS에 닿아, 테스트가 프록시 경로를 측정합니다. 이 규칙은 테스트가 쓰는 주소만 DIRECT로 보내고 다른 트래픽은 바꾸지 않습니다.

추가한 뒤 프록시 설정을 다시 불러오고 다시 테스트하세요.

도움말

Google Public DNS는 어떤 DNS인가요?

Google Public DNS는 미국의 Google이 운영하는 무료 공용 DNS입니다. 일반 DNS 주소는 8.8.8.8, 8.8.4.4(IPv6: 2001:4860:4860::8888, 2001:4860:4860::8844)이고, 암호화 DNS도 지원합니다: DoT, DoH. 서버가 전 세계 여러 곳에 있어, 조회는 가장 가까운 서버로 갑니다.

DNSSEC를 검증합니다. 서명이 맞지 않는 응답은 거부됩니다. 필터링하지 않습니다. 모든 이름이 그대로 조회됩니다.

Google Public DNS DNS 서버 주소

Google Public DNS를 쓸 때 입력할 값:

DNS (IPv4) 8.8.8.8, 8.8.4.4

DNS (IPv6) 2001:4860:4860::8888, 2001:4860:4860::8844

DoT / 개인 DNS dns.google

DoH https://dns.google/dns-query

Google Public DNS 설정 방법

Windows 11

설정 → 네트워크 및 인터넷 → Wi‑Fi 또는 이더넷 → 하드웨어 속성 → DNS 서버 할당 → 편집 → 수동. IPv4를 켜고 다음 주소를 입력합니다: 8.8.8.8, 8.8.4.4. 암호화하려면 'DNS over HTTPS'를 '켜기(수동 템플릿)'로 하고 템플릿에 다음을 입력합니다: https://dns.google/dns-query.

macOS

시스템 설정 → 네트워크 → Wi‑Fi(또는 이더넷) → 세부사항 → DNS에서 +를 눌러 다음 주소를 추가합니다: 8.8.8.8, 8.8.4.4. 암호화 DNS(https://dns.google/dns-query)는 구성 프로파일이 필요합니다.

iPhone과 iPad

설정 → Wi‑Fi → 네트워크 옆 ⓘ → DNS 구성 → 수동에서 다음 주소를 추가합니다: 8.8.8.8, 8.8.4.4. 해당 Wi‑Fi에만 적용됩니다. 모든 네트워크에서 암호화 DNS를 쓰려면 https://dns.google/dns-query용 DNS 프로파일을 설치하세요.

Android

설정 → 네트워크 및 인터넷 → 개인 DNS → 개인 DNS 제공업체 호스트 이름에 다음을 입력합니다: dns.google. 모든 네트워크에서 적용되고 암호화됩니다(DoT). 제조사마다 메뉴가 조금 다르니 설정에서 '개인 DNS'를 검색하세요.

공유기

공유기 관리 페이지(WAN 또는 DHCP 설정)에서 DNS 서버를 다음으로 바꿉니다: 8.8.8.8, 8.8.4.4. 네트워크의 모든 기기가 이를 사용합니다.

브라우저

Chrome: 설정 → 개인 정보 보호 및 보안 → 보안 → 보안 DNS 사용 → 맞춤설정에 https://dns.google/dns-query. Edge는 '개인 정보, 검색 및 서비스'에 같은 항목이 있습니다. Firefox: 설정 → 개인 정보 및 보안 → DNS over HTTPS → 최대 보호 → 사용자 지정에 https://dns.google/dns-query.

Linux

systemd-resolved: /etc/systemd/resolved.conf에 DNS=8.8.8.8 8.8.4.4 줄을 적고 systemctl restart systemd-resolved를 실행합니다. DoT를 쓰려면 주소를 8.8.8.8#dns.google 형식으로 적고 DNSOverTLS=yes를 추가합니다.

Google Public DNS를 중국 본토에서 쓸 수 있나요?

일반 DNS는 대개 응답하지만 서버가 중국 본토 밖에 있어 느리고, 차단된 사이트에 대한 응답은 도중에 위조될 수 있습니다. 암호화 DNS(DoH, DoT)는 자주 차단되거나 불안정합니다. 이 페이지에서 측정해 보세요. 응답이 없는 행은 내 네트워크에서 닿지 않는다는 뜻입니다.

Google Public DNS와 Cloudflare DNS, 어느 쪽이 빠른가요?

어디서나 더 빠른 쪽은 없습니다. 각자의 가장 가까운 서버가 얼마나 먼지, 통신사가 어떤 경로로 가는지가 결정합니다. 이 페이지는 약 20초 만에 둘과 목록의 다른 DNS를 내 네트워크에서 모두 측정하고, 위쪽에 Google Public DNS의 순위와 가장 빠른 곳과의 차이를 보여 줍니다.

Google Public DNS가 느린 이유는?

대개 거리 때문입니다. 가장 가까운 서버가 멀거나 통신사가 멀리 돌아갑니다. 프록시나 VPN을 쓰면 조회도 그쪽을 거쳐서 프록시 경로를 재게 됩니다(직접 연결 규칙으로 해결). 암호화 DNS를 느리게 하거나 막는 네트워크도 있습니다. 아직 아무도 묻지 않은 이름은 늘 더 오래 걸립니다('캐시 없음' 열). 목록에 확실히 더 빠른 DNS가 있으면 그쪽으로 바꾸세요.

테스트는 어떻게 하나요?

브라우저가 각 DNS에 직접 조회합니다. 이 사이트를 거치지 않습니다. 먼저 각 DNS와 연결을 열고 인기 이름 세 개를 한 번씩 조회해 캐시에 올립니다. 이 단계는 결과에 넣지 않습니다. 이어서 10라운드: 매번 모든 DNS를 한 번씩, 순서를 매번 섞어서 몇 곳씩 동시에 조회합니다. 네트워크가 잠깐 막혀도 마침 측정 중이던 한 곳이 아니라 모두에게 똑같이 영향을 줍니다. 한 라운드 걸러 어디에도 없는 무작위 이름도 조회합니다.

숫자는 중앙값이라 한 번 느린 것은 영향을 주지 않습니다. 시간은 브라우저가 요청마다 직접 기록한 네트워크 시간이라 페이지 스크립트가 늦출 수 없습니다. URL은 매번 새롭고 캐시를 거치지 않으므로 리졸버 자신만 답할 수 있습니다.

UDP와 DoT가 추정값인 이유는?

브라우저는 HTTPS 요청만 보낼 수 있습니다. 53번 포트 UDP 조회도, 853번 포트 TLS 연결(DoT)도, DoQ도 할 수 없고, 내 네트워크에서 이를 측정할 수 있는 웹사이트는 없습니다. 그런 숫자를 보여 주는 사이트는 자기 서버에서 측정하거나 추측한 것입니다.

이 페이지는 UDP와 DoT에 답하는 바로 그 서버로 DNS over HTTPS를 보냅니다(예: https://1.1.1.1/dns-query). 열린 연결에서 한 번의 조회는 그 서버까지 한 번 왕복과 리졸버 처리 시간이고, UDP나 DoT 조회도 똑같이 걸립니다. HTTP가 더하는 시간은 1 ms도 안 됩니다. 그래서 ≈입니다. 일반 DNS 서버가 HTTPS를 지원하지 않으면 숫자 대신 –로 표시합니다.

추정으로 알 수 없는 것: HTTPS는 그대로 두고 53번이나 853번만 차단·제한·변조하는 네트워크.

UDP, DoT, DoQ를 실측하려면 서버나 Linux 기기, 공유기에서 명령줄 도구(표 아래의 명령)를 실행하세요. 모든 프로토콜을 지원하고 같은 DNS 목록을 씁니다.

결과는 얼마나 믿을 수 있나요?

측정 방법은 첫 번째 질문에 있습니다. 또한 목록은 저장소의 scripts/verify.mjs로 여러 대륙에서 확인합니다. 모든 주소가 이 형식의 조회에 진짜 DNS 응답을 돌려줘야 하고, DNSSEC 검증은 각 업체의 설명이 아니라 직접 테스트한 결과입니다.

응답 읽기를 허용하는 DNS(Cloudflare, Google, Quad9, Control D, DNS.SB, DNS4EU, IIJ)는 페이지가 응답 내용도 확인해 진짜만 셉니다. 나머지는 시간만 잴 수 있고 내용은 읽을 수 없습니다.

여러 번, 가능하면 시간대를 바꿔 테스트하세요. 밤에 가장 빠른 곳이 혼잡 시간에도 그렇다는 보장은 없습니다.

프록시를 쓰고 있어요. 결과가 제 것인가요?

기본적으로는 아닙니다. 프록시나 VPN이 켜져 있으면 브라우저가 그것을 거쳐 각 DNS에 닿기 때문에, 테스트는 프록시 경로를 측정합니다(해외 DNS가 모두 프록시 서버만큼 빠르게 보입니다). 기기나 공유기에 설정한 DNS는 보통 직접 조회되므로 실제로 얻는 속도가 아닙니다.

내 네트워크를 측정하려면 직접 연결 규칙(진행 표시 옆 버튼)을 추가하세요. 이 테스트가 쓰는 주소만 정확한 호스트 이름과 단일 IP로 직접 연결하고 다른 것은 바꾸지 않습니다. Clash/Mihomo, Surge, Shadowrocket, Quantumult X, Loon, sing-box, Xray를 지원하며, 대부분 이 사이트에서 규칙을 받아 최신으로 유지할 수 있습니다.

'캐시 없음'은 무슨 뜻인가요?

인기 이름은 큰 리졸버라면 이미 캐시에 있어 어디서나 빨리 답합니다. 최근 아무도 조회하지 않은 이름은 리졸버가 먼저 그 사이트의 DNS 서버에 물어봅니다. 테스트는 Cloudflare DNS에 호스팅된 영역의 무작위 이름을 씁니다. Cloudflare 서버는 중국 본토를 빼면 거의 전 세계에 있습니다.

이 시간은 사이트마다 DNS 서버 위치에 따라 달라서 보여 주기만 하고 순위에는 쓰지 않습니다. 중국 본토 DNS가 여기서 느려 보이는 것은 영역 서버가 해외에 있기 때문이며, 중국 사이트(DNS 서버가 중국 내)에는 빠르게 답합니다.

어떤 걸 고르면 되나요?

맨 위의 DNS가 좋은 기본 선택입니다. 차이가 몇 ms뿐이면 다른 중요한 점으로 고르세요: Quad9와 OpenDNS는 알려진 악성·피싱 사이트를 차단합니다. Mullvad, Quad9, Wikimedia는 누가 무엇을 조회했는지 기록하지 않습니다. DNSSEC를 검증하는 DNS는 서명된 도메인의 위조 응답을 거부합니다.

기기에 일반 DNS 서버 주소만 넣을 수 있다면(대부분의 공유기, 오래된 시스템) UDP 열을 보세요. 가장 빠른 일반 DNS가 1위와 다르면 1위 아래 줄에 나옵니다.

네트워크나 통신사가 조회 내용을 보지 못하게 하려면 DoT나 DoH 주소를 쓰세요. 일반 DNS는 암호화되지 않습니다.

DNS는 어떻게 바꾸나요?

Android 9 이상: 설정 → 네트워크 → 개인 DNS → DoT 호스트 이름(예: one.one.one.one) 입력.

iPhone과 Mac: Wi-Fi 네트워크마다 DNS 서버 입력. 암호화 DNS는 업체 웹사이트의 구성 프로파일을 설치.

Windows 11: 설정 → 네트워크 → 연결 → DNS 서버 할당 → 수동, 서버를 입력하고 DNS over HTTPS 켜기.

공유기: DHCP나 WAN 설정에 DNS 서버를 넣으면 네트워크의 모든 기기가 사용합니다.

브라우저만: Chrome, Edge, Firefox의 '보안 DNS'에서 업체를 고르거나 DoH 주소를 붙여 넣습니다.

이 페이지의 주소는 클릭하면 복사됩니다.

DNSSEC란?

DNSSEC는 도메인이 자기 DNS 레코드에 서명하는 방식입니다. 검증하는 DNS는 서명을 확인하고 맞지 않으면 거부하므로, 중간의 누구도 서명된 도메인의 위조 주소를 건넬 수 없습니다. ✓는 검증하는 DNS입니다(일부러 서명을 망가뜨린 dnssec-failed.org를 거부하는지로 테스트). 서명된 도메인에만 효과가 있지만 손해는 없습니다.

114DNS나 Baidu DNS가 없는 이유는?

일반 DNS만 제공하고 서버가 HTTPS에 전혀 응답하지 않아, 브라우저로는 어떤 방법으로도 닿지 않습니다. 대만의 Quad101도 확인 당시 DoH가 해외에서 응답하지 않아 뺐습니다.

ECS란? 왜 표시하지 않나요?

EDNS Client Subnet: 일부 DNS는 내 주소의 일부를 사이트의 DNS 서버에 알려, CDN이 리졸버가 아니라 내 근처 서버를 고르게 합니다. 다운로드와 동영상이 빨라질 수 있지만 개인정보 보호는 조금 줄어듭니다.

표에 없는 이유는 고정된 성질이 아니기 때문입니다. 확인해 보니 같은 DNS가 장소와 프로토콜에 따라 전하기도 하고 안 하기도 해서, 예·아니요 어느 쪽도 오해를 부릅니다.

데이터를 수집하나요?

아니요. 조회는 브라우저에서 각 DNS로 바로 가고, 내용은 공개된 인기 사이트와 무작위 이름뿐이라 내 정보는 없습니다. 이 사이트는 결과를 받지 않습니다. 평소의 DNS 조회와 마찬가지로 각 DNS는 내 주소를 볼 수 있고, 각자의 개인정보 처리방침이 적용됩니다. 코드는 GitHub에 공개되어 있습니다.
