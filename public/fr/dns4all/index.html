Aide

Qu’est-ce que DNS4ALL ?

DNS4ALL est un service DNS public et gratuit proposé par DNS4ALL, basé en Pays-Bas. Ses adresses DNS classiques sont 194.0.5.3 (IPv6 : 2001:678:8::3), et il propose aussi du DNS chiffré : DoT, DoH, DoQ. Il sert surtout une région (Pays-Bas) : à proximité, il peut être le plus rapide, mais de loin il est généralement plus lent que les grands services mondiaux.

Il vérifie DNSSEC (la signature des domaines) : les réponses mal signées sont refusées, elles ne peuvent donc pas être falsifiées. Il ne filtre rien : tous les noms sont résolus normalement. Il est géré par une organisation à but non lucratif.

Adresses des serveurs DNS de DNS4ALL

Pour utiliser DNS4ALL, saisissez :

DNS (IPv4) 194.0.5.3

DNS (IPv6) 2001:678:8::3

DoT / DNS privé dot.dns4all.eu

DoH https://doh.dns4all.eu/dns-query

DoQ quic://dot.dns4all.eu

Comment configurer DNS4ALL

Windows 11

Paramètres → Réseau et Internet → Wi‑Fi ou Ethernet → Propriétés du matériel → Attribution du serveur DNS → Modifier → Manuel. Activez IPv4 et saisissez 194.0.5.3. Pour le chiffrer, réglez DNS sur HTTPS sur Activé (modèle manuel) et saisissez https://doh.dns4all.eu/dns-query.

macOS

Réglages Système → Réseau → Wi‑Fi (ou Ethernet) → Détails → DNS : cliquez sur + et ajoutez 194.0.5.3. Pour le DNS chiffré (https://doh.dns4all.eu/dns-query), il faut installer un profil de configuration.

iPhone et iPad

Réglages → Wi‑Fi → touchez ⓘ à côté du réseau → Configurer le DNS → Manuel, puis ajoutez 194.0.5.3. Cela ne vaut que pour ce réseau Wi‑Fi. Pour du DNS chiffré sur tous les réseaux, installez un profil DNS pour https://doh.dns4all.eu/dns-query.

Android

Paramètres → Réseau et Internet → DNS privé → Nom d’hôte du fournisseur DNS privé, et saisissez dot.dns4all.eu. Valable sur tous les réseaux, et chiffré (DoT). Le menu varie un peu selon la marque : cherchez « DNS privé » dans les paramètres.

Box ou routeur

Dans l’interface d’administration de votre box ou routeur (réglages WAN ou DHCP), indiquez 194.0.5.3 comme serveurs DNS. Tous les appareils de votre réseau l’utiliseront alors.

Navigateur

Chrome : Paramètres → Confidentialité et sécurité → Sécurité → Utiliser un DNS sécurisé → Personnalisé, et saisissez https://doh.dns4all.eu/dns-query. Edge propose la même option dans Confidentialité, recherche et services. Firefox : Paramètres → Vie privée et sécurité → DNS via HTTPS → Protection maximale → Personnalisé, et saisissez https://doh.dns4all.eu/dns-query.

Linux

Avec systemd-resolved : ajoutez DNS=194.0.5.3 dans /etc/systemd/resolved.conf, puis lancez systemctl restart systemd-resolved. Pour DoT, écrivez l’adresse sous la forme 194.0.5.3#dot.dns4all.eu et ajoutez DNSOverTLS=yes.

DNS4ALL fonctionne-t-il en Chine continentale ?

Son DNS classique répond en général, mais plus lentement, car les serveurs sont hors de Chine continentale, et les réponses pour les sites bloqués peuvent être falsifiées en chemin. Son DNS chiffré (DoH, DoT) est souvent bloqué ou instable. Le plus simple pour savoir : lancez le test de cette page. Si le résultat indique « Injoignable depuis votre réseau », votre réseau ne le joint pas.

DNS4ALL ou Quad9 DNS : lequel est le plus rapide ?

Aucun n’est plus rapide partout. Tout dépend de la distance entre vous et le serveur le plus proche de chacun, et du chemin qu’emprunte votre fournisseur d’accès pour y aller. Cette page mesure DNS4ALL depuis votre propre réseau en quelques secondes. Pour le comparer aux autres, lancez le test de la page d’accueil : il mesure tous les serveurs de la liste et vous montre le plus rapide chez vous.

Pourquoi DNS4ALL est-il lent chez moi ?

Le plus souvent, c’est la distance : son serveur le plus proche est loin de vous, ou votre fournisseur d’accès fait un détour pour y arriver. Avec un proxy ou un VPN actif, les requêtes passent aussi par lui et le test mesure la route du proxy (les règles directes corrigent cela). Certains réseaux ralentissent ou bloquent le DNS chiffré. Et un nom que personne n’a encore demandé prend toujours plus de temps (voir le temps de première requête sous le résultat). Pour savoir si un autre serveur est plus rapide chez vous, testez-les tous sur la page d’accueil.

Comment changer de DNS ?

Android 9 et plus : Paramètres → Réseau → DNS privé, puis saisissez le nom d’hôte DoT (par exemple one.one.one.one). Valable sur tous les réseaux, et chiffré.

iPhone et Mac : saisissez les serveurs DNS pour chaque réseau Wi-Fi. Pour le DNS chiffré, installez un profil de configuration depuis le site du fournisseur.

Windows 11 : Paramètres → Réseau → votre connexion → Attribution du serveur DNS → Manuel. Saisissez les serveurs et activez DNS sur HTTPS.

Box ou routeur : indiquez les serveurs DNS dans ses réglages DHCP ou WAN, et tous les appareils du réseau les utiliseront.

Le navigateur seulement : Chrome, Edge et Firefox ont un réglage DNS sécurisé où vous choisissez un fournisseur ou collez une adresse DoH.

Chaque serveur a sa propre page avec la configuration pas à pas. Cliquez sur n’importe quelle adresse de cette page pour la copier.

J’utilise un proxy. Le résultat est-il toujours celui de mon réseau ?

Pas par défaut. Avec un proxy ou un VPN actif, le navigateur joint les serveurs DNS à travers lui : le test mesure la route du proxy, et tous les serveurs à l’étranger semblent à peu près aussi rapides que votre serveur proxy. Le DNS réglé sur votre appareil ou votre box est en principe interrogé directement, ces chiffres ne correspondent donc pas à ce que vous auriez en vrai.

Pour tester votre propre réseau, ajoutez les règles directes (le bouton à côté de la barre de progression). Elles envoient en direct uniquement les adresses utilisées par ce test, par nom d’hôte exact et IP unique, sans toucher au reste du trafic. Clash/Mihomo, Surge, Shadowrocket, Quantumult X, Loon, sing-box et Xray sont pris en charge, et la plupart peuvent charger les règles depuis ce site pour rester à jour.

Comment fonctionne le test ?

Votre navigateur interroge chaque serveur DNS directement ; rien ne passe par ce site.

Il se connecte d’abord à ce serveur et demande une fois trois noms populaires, pour qu’ils soient dans son cache. Cette étape ne compte pas. Viennent ensuite 10 tours, une requête par tour, si bien qu’un coup de mou passager de votre réseau ne décide pas du résultat. Un tour sur deux demande aussi un nom aléatoire qui n’existe pas.

Les résultats sont des médianes : une requête lente isolée ne fait pas chuter le score. Les temps viennent du chronométrage réseau du navigateur lui-même, que les scripts de la page ne peuvent pas ralentir. Chaque requête va vers une nouvelle URL et contourne tous les caches : seul le serveur DNS lui-même peut répondre.

Pourquoi UDP et DoT sont-ils estimés ?

Parce que le navigateur ne peut pas les mesurer. Une page web ne peut faire que des requêtes HTTPS : elle ne peut pas envoyer de DNS classique en UDP (port 53), de DNS chiffré en TLS (DoT, port 853) ni de DoQ. Aucun site ne peut mesurer cela depuis votre réseau ; un site qui affiche ces chiffres les a mesurés depuis son propre serveur, ou les a devinés.

Ce que fait cette page à la place : elle envoie du DoH, c’est-à-dire du DNS chiffré via HTTPS, au serveur même qui répond en UDP et en DoT (par exemple https://1.1.1.1/dns-query). Une fois la connexion ouverte, une requête coûte un aller-retour jusqu’à ce serveur plus son temps de traitement. Une requête UDP ou DoT coûte exactement la même chose ; HTTPS ajoute bien moins d’une milliseconde. D’où le ≈. Quand le serveur DNS classique d’un fournisseur ne parle pas HTTPS, vous voyez un – plutôt qu’un chiffre inventé.

Ce qu’une estimation ne voit pas : un réseau qui bloque, ralentit ou trafique les ports 53 ou 853 mais laisse passer HTTPS.

Pour mesurer vraiment UDP, DoT et DoQ, lancez la commande de l’encadré ligne de commande de cette page sur un serveur, une machine Linux ou un routeur. Elle parle tous les protocoles et teste ce serveur avec celui auquel on le compare.

Les résultats sont-ils fiables ?

La méthode de mesure est décrite dans Comment fonctionne le test ? En plus, la liste est vérifiée depuis plusieurs continents avec scripts/verify.mjs (dans le dépôt du code) : chaque adresse doit répondre à ce type de requête par une vraie réponse DNS, et la prise en charge de DNSSEC est testée, pas reprise des annonces des fournisseurs.

Cloudflare, Google, Quad9, Control D, DNS.SB, DNS4EU et IIJ autorisent une page web à lire leurs réponses : la page les vérifie une à une et ne compte que les vraies. Pour les autres, le navigateur peut chronométrer la réponse mais pas la lire.

Relancez le test plusieurs fois, idéalement à différentes heures : le plus rapide la nuit ne l’est pas forcément aux heures de pointe.

Que veut dire Première requête ?

Les noms populaires sont déjà dans le cache de tous les grands serveurs DNS, qui y répondent donc vite. Pour un nom que personne n’a demandé depuis un moment, c’est différent : le serveur doit d’abord interroger les serveurs DNS du site lui-même, puis vous transmettre la réponse. C’est ce qu’on appelle ici une première requête.

Le test utilise des noms aléatoires hébergés chez Cloudflare, dont les serveurs DNS sont présents presque partout sauf en Chine continentale. Ce temps dépend de l’emplacement des serveurs DNS de chaque site, qui varie d’un site à l’autre : il est affiché mais pas classé. Les serveurs de Chine continentale affichent ici une première requête lente parce que les serveurs de ces noms sont à l’étranger ; pour les sites chinois, ils sont rapides.

Qu’est-ce que DNSSEC ?

En bref : les domaines signent leurs enregistrements DNS pour que les réponses ne puissent pas être falsifiées. Un serveur qui vérifie DNSSEC contrôle la signature et refuse les réponses qui ne correspondent pas : personne en chemin ne peut vous glisser une fausse adresse. Un ✓ indique que le serveur le vérifie : nous testons avec un domaine volontairement cassé, dnssec-failed.org, qu’il doit refuser. Cela ne protège que les domaines signés, mais n’a aucun inconvénient.

Qu’est-ce que l’ECS, et pourquoi n’est-il pas affiché ici ?

L’ECS (EDNS Client Subnet), c’est quand le serveur DNS transmet une partie de votre adresse IP aux serveurs DNS du site, pour qu’un CDN choisisse un serveur près de vous plutôt que près du serveur DNS. Les téléchargements et la vidéo peuvent aller plus vite, au prix d’un peu d’information sur l’endroit où vous êtes.

Il n’est pas affiché parce qu’il n’est pas fixe : lors de nos vérifications, le même serveur le transmettait depuis certains endroits et par certains protocoles, mais pas depuis d’autres. Un simple oui ou non vous induirait en erreur.

Pourquoi 114DNS et Baidu DNS ne sont-ils pas testés ?

Ils ne proposent que du DNS classique, et leurs serveurs ne répondent pas du tout en HTTPS : un navigateur n’a aucun moyen de les joindre. Quad101 (Taïwan, Chine) n’y figure pas non plus : son DoH ne répondait pas depuis d’autres régions lors de nos vérifications.

Collectez-vous mes données ?

Aucun résultat ni rien sur vous n’est conservé. Les requêtes du test partent directement de votre navigateur vers chaque résolveur, pour des sites publics populaires et des noms aléatoires : rien sur vous n’y figure. Vos résultats restent dans votre navigateur. C’est seulement quand vous cliquez sur Partager qu’ils sont inscrits dans le lien (les temps de chaque résolveur, sans adresse IP ; ajouter votre pays ou région est votre choix).

Une seule chose passe par le serveur de 1ms.dog (à Tokyo) : pour montrer quel résolveur votre appareil utilise vraiment, la page résout un nom aléatoire sous l.1ms.dog, dont le serveur DNS est le nôtre, et après le test envoie un tel nom à travers chaque résolveur pour voir lequel de ses serveurs vous répond. Ce serveur voit l’adresse du résolveur qui a demandé et, si ce résolveur la transmet, votre réseau (ECS : le début de votre adresse, par exemple 203.0.113.0/24). Il les garde en mémoire 2 minutes, le temps que la page les récupère sur api.l.1ms.dog, puis les oublie ; rien n’est écrit sur disque ni dans un journal. La page ne les montre qu’à vous ; elles ne sont jamais dans le lien ni la carte de partage.

Comme pour toute requête DNS, chaque résolveur voit votre adresse IP et sa propre politique de confidentialité s’applique. Le code est ouvert, sur GitHub.
